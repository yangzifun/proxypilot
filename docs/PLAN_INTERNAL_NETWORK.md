# 方案：Agent ↔ 面板 内网直连（WARP 组网）

> 状态：**待确认**（未实施）
> 目标版本：V25.0 / Agent 1.9.0

---

## 一、现状

| 项 | 当前值 |
|---|---|
| 面板监听 | `:80`（公网）、`:443`（节点直连，Let's Encrypt 证书） |
| Agent 连面板 | `https://agent.yangzifun.org:443`（公网 IP，TLS） |
| 网页入口 | Cloudflare → `:80` |
| 组网网卡 | 面板 `100.96.0.18/32`（`CloudflareWARP`，Zero Trust 私有网络） |
| 数据通道 | WSS 每 2 秒推指标 + HTTP poll 60 秒兜底 |

问题：所有 Agent 流量都要经过公网入口（TLS 握手、证书、公网带宽、暴露面）。

---

## 二、目标

1. Agent 优先经**内网 `100.96.0.18`** 直连面板，不经过公网 HTTP 入口
2. 公网域名保留为**兜底通道**，内网不可用时自动回落
3. 数据实时性不降级（指标 2 秒、任务/终端秒级下发）
4. 公网入口仅保留网页访问，减小攻击面

---

## 三、"不再使用 HTTP" 的说明

现有通道是 **WebSocket**：握手阶段是 HTTP `Upgrade`，之后是自定义 JSON 帧。
如果要做到字面意义的"零 HTTP"，只有两条路：

| 方案 | 说明 | 代价 |
|---|---|---|
| **A. WS over 内网明文 HTTP**（推荐） | 内网已是 WARP/WireGuard 加密隧道，去掉 TLS 与证书，省一次握手 | 小，复用现有全部逻辑 |
| B. 自研 TCP 帧协议 | 完全不用 HTTP，自己实现长度前缀 + 分帧 + 心跳 + 重连 | 3–5 天，且失去 WS 的成熟实现 |

**结论：推荐 A。** 数据本身已由 WireGuard 加密，"不用 HTTP" 的实际收益（省几十字节握手头）远小于自研协议的风险。

## 四、目标架构

```
┌─────────────── 节点服务器（多台）────────────────┐
│  Agent                                          │
│    ├─ 首选：ws://100.96.0.18:8080/api/agent/ws   │  ← 内网，明文，WARP 加密
│    │         http://100.96.0.18:8080/api/agent/poll（60s 兜底）
│    └─ 回落：wss://agent.yangzifun.org/api/agent/ws
└─────────────────────────────────────────────────┘
                      │  WARP 私有网络（100.64.0.0/10）
                      ▼
┌─────────────── 面板 100.96.0.18 ─────────────────┐
│  :8080  内网专用监听（仅 /api/agent/*、/api/shell/agent/*）│
│  :80    公网网页（Cloudflare）                     │
│  :443   公网 Agent 兜底（保留）                     │
└─────────────────────────────────────────────────┘
```

## 五、改动清单

### 5.1 面板

| 改动 | 说明 |
|---|---|
| 新增内网监听 | `PP_AGENT_INTERNAL_ADDR=100.96.0.18:8080`，仅绑定 WARP 网卡 |
| 复用白名单 | 内网监听同样走 `agentOnlyHandler`（只放行 Agent 接口） |
| 新增设置项 | `agent_internal_url`（默认 `http://100.96.0.18:8080`） |
| 下发端点 | WS 推送 `{"type":"endpoint","internal":"...","external":"..."}` |
| 统计 | 记录每个节点当前走内网还是公网（新增 `agent_transport` 字段） |

### 5.2 Agent

| 改动 | 说明 |
|---|---|
| 配置 | `PROXYPILOT_INTERNAL_URL`、`PROXYPILOT_URL`（兜底） |
| 选路 | 启动先探测内网（3 秒超时）→ 可用则用内网，否则用公网 |
| 周期探测 | 每 5 分钟探测内网，恢复后切回 |
| 统一基址 | WS / poll / shell 隧道全部使用当前生效基址 |
| 日志 | 记录当前通道（`internal` / `external`）便于排查 |

### 5.3 数据库

```sql
ALTER TABLE servers ADD COLUMN agent_transport VARCHAR(16) NOT NULL DEFAULT '';
-- internal / external
```

## 六、安全

1. **只绑内网**：`:8080` 绑定 `100.96.0.18`，不暴露公网
2. **防火墙**：仅允许 `100.64.0.0/10` 访问 8080
   ```
   iptables -A INPUT -p tcp --dport 8080 ! -s 100.64.0.0/10 -j DROP
   ```
3. **令牌不变**：仍要求 `ag_` 接入令牌，白名单仅限制接口范围
4. **公网入口不变**：网页仍走 Cloudflare，443 仍保留给兜底

---

## 七、灰度与回滚

| 阶段 | 动作 | 风险 |
|---|---|---|
| 1 | 面板加内网监听（不影响现有流量） | 无 |
| 2 | 挑选 1 台节点，手工把 `PROXYPILOT_URL` 改为内网地址 | 单节点 |
| 3 | 验证 10 分钟：WS 连接、指标、任务、终端 | 单节点 |
| 4 | 通过 WS 下发端点给全部节点，Agent 自动切换 | 可批量回滚 |
| 5 | 观察 24 小时后，可考虑关闭 443 兜底 | — |

**回滚**：`UPDATE app_settings SET value='https://agent.yangzifun.org' WHERE key='agent_access_url'`，节点下一次探测（≤5 分钟）自动回到公网。
