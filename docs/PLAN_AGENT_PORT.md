# 方案：取消公网 Agent 域名，改用专用端口直连

> 状态：**待确认**
> 目标版本：V25.1 / Agent 1.9.1
> 前置：V25.0 已实现内网监听 `100.96.0.18:8080`

---

## 一、变更概要

| 项 | 现状 | 变更后 |
|---|---|---|
| 管理后台网页 | Cloudflare → 源站 `:80` | **不变** |
| 用户端网页 | Cloudflare → 源站 `:80` | **不变** |
| Agent 连接 | `https://agent.yangzifun.org:443` | **取消** |
| `agent.yangzifun.org` DNS | A 记录指向源站 | **删除** |
| 源站 `:443` 监听 | Agent 公网入口 | **关闭** |
| Let's Encrypt 证书 | 用于 443 | **停止续期并删除** |
| Agent 新通道 | — | **专用端口 `:8080`（内网 IP 直连）** |

---

## 二、目标架构

```
        ┌─────────────────────────────┐
        │  Cloudflare（橙云，CDN）     │
        └──────────────┬──────────────┘
                       │ :80
┌──────────────────────▼──────────────────────────┐
│  面板 23.254.172.198                             │
│    :80    公网网页（管理后台 / 用户端）           │
│    :443   ← 关闭                                 │
│    :8080  Agent 专用端口（绑定 100.96.0.18）      │
└──────────────────────▲──────────────────────────┘
                       │ 内网 IP 直连
        ┌──────────────┴──────────────┐
        │  各节点 Agent（WARP 组网）   │
        │  ws://100.96.0.18:8080/...  │
        └─────────────────────────────┘
```

要点：

- 网页链路完全不动
- Agent 只走内网 IP + 专用端口
- 公网不再暴露任何 Agent 入口

---

## 三、端口与协议设计

| 项 | 设计 |
|---|---|
| 端口 | **8080**（可配：`PP_AGENT_PORT`） |
| 绑定 | 仅 `100.96.0.18`（不监听 `0.0.0.0`） |
| 协议 | WebSocket over 明文 HTTP（WARP 隧道已加密） |
| 证书 | **不需要**（省 1–2 个 RTT） |
| 鉴权 | `ag_` 接入令牌（不变） |
| 白名单 | `/api/agent/*`、`/api/shell/agent/*`、`/healthz` |

> 说明：WS 握手本质是 HTTP Upgrade。若坚持"零 HTTP"，需自研 TCP 帧协议（+3~5 天），不建议。

## 四、面板改动

| 文件 | 改动 |
|---|---|
| `config.go` | 新增 `PP_AGENT_PORT`（默认 8080）、`PP_AGENT_BIND`（默认 `100.96.0.18`） |
| `main.go` | 仅监听 `bind:port`；**删除 443 TLS 监听代码** |
| `settings_store.go` | `agent_internal_url` 作为唯一连接地址；`agent_access_url` 标记为废弃 |
| `agentkey.go` | 安装命令的 `--url` 改为内网地址 |

## 五、Agent 改动

| 项 | 改动 |
|---|---|
| 配置 | `PROXYPILOT_URL=http://100.96.0.18:8080`（唯一地址） |
| 采样 | 内网 200ms（可配 `PROXYPILOT_METRIC_MS`） |
| 连接 | 单条 WSS 常驻；HTTP poll 降为 60s 保底 |
| 探测 | 启动探测 `/healthz`，失败则指数退避重试（1s→30s） |
| 日志 | 记录当前通道与 RTT |

## 六、安装命令

```bash
curl -fsSL http://100.96.0.18:8080/api/agent/install.sh \
  | sudo sh -s -- --key ag_xxx --url http://100.96.0.18:8080
```

面板生成命令时自动使用 `agent_internal_url`。

## 七、迁移步骤（4 阶段）

### 阶段 1：启用专线（不停旧通道）

1. 面板加 `PP_AGENT_PORT=8080`、`PP_AGENT_BIND=100.96.0.18`
2. 防火墙放行 WARP 网段访问 8080
3. 保持 443 与域名不变

验证：单节点 `curl http://100.96.0.18:8080/healthz` 通。

### 阶段 2：灰度切 1 台

```bash
# 节点上
sed -i 's#https://agent.yangzifun.org#http://100.96.0.18:8080#' /etc/proxypilot-agent.conf
systemctl restart proxypilot-agent
```

观察 10 分钟：WS 连接、指标 200ms、任务下发、实时终端。

### 阶段 3：全量切换

- 面板通过 WS 推送 `{"type":"endpoint","internal":"http://100.96.0.18:8080"}`
- Agent 1.9.1 收到后自动切址并重连
- 确认 18/18 走内网：`servers.agent_transport='internal'`

### 阶段 4：下线公网入口

```bash
# 1. 关闭 443 监听（改代码后重启即可）
# 2. 防火墙移除 443 放行
iptables -D INPUT -p tcp --dport 443 -j ACCEPT
# 3. 停止证书续期并删除
/root/.acme.sh/acme.sh --remove -d agent.yangzifun.org
rm -rf /etc/proxypilot/tls
crontab -l | grep -v acme.sh | crontab -
# 4. Cloudflare 删除 DNS 记录 agent.yangzifun.org
```

## 九、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **WARP 故障 → 节点全失联** | 所有节点无法上报，面板不可控 | 见下方建议 |
| 端口被安全组拦截 | 新装节点连不上 | 部署前在节点验证 `curl` |
| 面板 IP 变更 | 全部节点失联 | 内网 IP 固定，变更需重新下发 |
| 明文传输 | 理论上可嗅探 | WARP WireGuard 加密，公网不可达 |

### 关于"全失联"风险的两种选择

| 选择 | 说明 |
|---|---|
| **A. 完全取消公网入口**（你当前要求） | 结构最干净，但 WARP 故障时节点只能等恢复 |
| **B. 保留公网端口但默认关闭** | 需要时临时打开防火墙 + 打开监听，作应急通道 |

推荐做法：**代码保留 443 能力，默认不启用**（配置为空即不监听），需要应急时改一个环境变量重启即可。这样既满足"取消域名"，又留了后路。
