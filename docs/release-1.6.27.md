# ProxyPilot 1.6.27 发布说明（修复短暂心跳空档误报离线）

日期：2026-11-26
版本：面板 V1.6.27 / Agent 1.4.2 / VPN 客户端 1.4.1

## 问题

用户收到「服务器离线」邮件：

- 服务器：香港2；
- Agent 1.4.2；
- 最后心跳到判定离线仅 **94 秒**；
- 设备实际仍在线，属于短暂心跳空档误报。

## 根因

`agentOfflineTimeoutMs` 原规则：

- `poll * 4`，最低 60 秒；
- 香港2 的 `agent_next_poll_sec=20`，离线阈值只有 80 秒；
- Agent 采集/网络抖动 94 秒就被判定离线，触发离线邮件；
- 恢复后又会触发恢复邮件，形成频繁上下线通知。

## 修复

### 1. 离线阈值提高到 5 分钟

```text
timeout = max(poll * 6, 300 秒)
```

- 20 秒轮询：原来 80 秒，现在 300 秒；
- 60 秒轮询：原来 240 秒，现在 360 秒；
- 900 秒轮询：仍封顶 3600 秒；
- 94 秒级空档不再被判定离线。

### 2. 新装机器首次心跳不通知

- 从未上报过心跳的服务器：
  - 只记录 offline 状态；
  - 不再发送「服务器离线」邮件；
  - 避免新机器安装阶段误触发。
- 首次心跳恢复时：
  - 不发送「服务器恢复」邮件；
  - 只有曾经在线、真正经历离线阈值的服务器才发恢复通知。

### 3. 保留通知记录与上下线记录

V1.6.26 已有的记录能力继续生效：

- `notification_logs`：通知发送/跳过/失败；
- `server_status_events`：设备上线/离线与时长；
- 日志页「通知记录」「设备上下线」Tab 可查看。

- 301 秒才判定离线；
- 94 秒空档测试保持在线；
- server 构建、测试全绿；
- 面板 healthz V1.6.27；

## 说明

- 真实离线仍会在约 5 分钟后告警；
- 如果希望更快/更慢告警，可继续把阈值做成后台设置项；
- 现有通知冷却仍为 10 分钟，同一节点不会连续刷邮件；
- 通知记录可用来确认每次告警/恢复是否真实送达。
