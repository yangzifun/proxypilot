# Windows 客户端上行丢包（20~25%）排查记录

## 现象

- 连上任意节点后 ping 丢包稳定在 20~25%，RTT 正常（150~250ms）
- `ping 节点公网 IP` 0% 丢包（直连，不进隧道）
- `ping 网关 10.88.x.1` 同样丢包 —— 说明与公网、NAT、运营商无关
- 节点侧 `bad_pkt` 占比与丢包率一致

## 已排除

| 怀疑 | 依据 |
|---|---|
| 运营商 ICMP 限速 / Cloudflare 限速 | 网关本地应答也丢 |
| 节点 NAT / conntrack | conntrack 475/65536，网卡 TX dropped=0 |
| rp_filter / WARP 抢路由 | rp_filter=2，本地应答不经路由 |
| MTU 分片 | 32 字节 ICMP 远小于 MTU；钳到 1200 后仍丢 20% |
| 客户端发送队列溢出 | `uplink_dropped = 0` |
| 链路层丢包 | QUIC `PacketsLost = 0` |
| 双重分帧（历史 bug） | 2.17 已修，下行恢复正常 |

## 已确认

节点 `StripPadding` 判坏包，客户端自检 `inner_bad` 同时计数。典型样本：

```
帧 40 字节，IP 头声明 490 字节   | 45 00 01 ea ... 10.88.3.10 -> 220.181.104.180
帧 40 字节，IP 头声明 52 字节    | TCP SYN，TCP 选项（12 字节）整段缺失
帧 52 字节，IP 头声明 490 字节   | 同一个包的另一次交付，多了 12 字节
```

**同一个报文的两次交付长度不同（40 / 52）**，内容一致 —— 说明截断发生在
Wintun / 内核交付环节，不是我们的分帧或队列。

读长度分布（每 10 秒累计，MTU=1200 时）：

```
40:146  52:71  77:30  88:34  1200:16  490:7  407:3 ...
```

`40`、`52` 这类「恰好等于各种头部长度」的读数非常多，正是异常包的来源。

## 未解决

- 关闭 LSO / ChecksumOffload / RSC / RSS 在 Wintun 网卡上失败（exit 1，驱动不暴露这些属性）
- MTU 钳到 1200 无效，说明与分段大小无关
- 跨读取拼接（2.32）会把后续新包一起污染，导致 100% 丢包，已回滚
